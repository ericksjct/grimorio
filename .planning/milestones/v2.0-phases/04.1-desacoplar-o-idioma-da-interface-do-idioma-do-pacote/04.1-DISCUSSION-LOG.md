## Nome/escola em modo misto

### Q1 — Nome da magia com UI em português lendo pack em inglês

| Opção | Descrição | Selecionada |
|-------|-----------|-------------|
| Idioma do pack | `spellName(s, versionLang)` em todo lugar; card coerente, alinha com busca e ordenação que já usam `versionLang` | ✓ |
| Idioma da UI | `spellName(s, lang)` como hoje; título PT sobre descrição EN; exigiria mudar busca/ordenação também | |
| Você decide | Deixar a critério do planner | |

**Notas:** Enquadramento entregue antes da pergunta — `adaptSpell` grava `desc`/`descHtml`/`upgrade` com o mesmo HTML nas duas chaves, então o **nome é o único campo com dois valores reais**. Para packs SRD a escolha é indistinguível de "UI com fallback ao original", porque `pt = displayName || name` = o nome EN.

### Q2 — Vocabulário derivado pelo app (escola, Sim/Não, rótulos)

**Primeira tentativa:** o usuário respondeu *"quero que você pesquise as melhores práticas desse tipo de problema na internet"* em vez de escolher. Pesquisa executada (3 buscas: separação UI/content locale, prior art de display vs content language, WCAG lang em conteúdo misto) e apresentada antes de reformular.

| Opção | Descrição | Selecionada |
|-------|-----------|-------------|
| Idioma da UI, sempre | `hifiFilterConfig(uiLang)` + `schoolName(idx, uiLang)` + `hifiSchoolFilterLabel(v, uiLang)`; só valores de `class` e collator ficam em `versionLang` | ✓ |
| Idioma do pack, como hoje | Mantém `versionLang`; produz "Necromancy · 3º nível" e rótulos EN em UI PT | |
| Você decide | Planner atribui o dono de cada call site | |

**Notas:** Achado que motivou a pergunta — `hifiFilterConfig` serve dois papéis semânticos hoje: rótulos de chrome (`tt(lang, ...)`, `bool()`) e extração de dados (`get`). Pesquisa apontou os três precedentes registrados em CONTEXT.md §specifics (Netflix/Chrome, WCAG 3.1.1+3.1.2, regra de um valor por papel semântico). Também registrada a nota honesta de que pelo critério Netflix o nome seguiria a UI com fallback — o que converge com a escolha de Q1 no caso SRD.

### Q3 — A11y: como marcar o idioma no documento

| Opção | Descrição | Selecionada |
|-------|-----------|-------------|
| `<html lang>`=UI + `lang` nas partes | Documento no idioma da UI; 5 sinks `dangerouslySetInnerHTML` + nome da magia recebem `lang` próprio | ✓ |
| `<html lang>`=UI, sem marcar partes | Diff mínimo; passa 3.1.1, falha 3.1.2 sempre que UI e pack divergem | |
| `<html lang>` segue o pack | Quebra o chrome, que é a maior parte do texto da página | |

**Notas:** A11y é restrição travada em PROJECT.md. Custo real: um atributo em ~6 containers, zero JS novo.

### Q4 — Filtro de classe

**Pergunta interrompida pelo usuário para esclarecimento:** *"na opção 1, o que acontece se eu fizer um pack só em inglês com só as classes em inglês preenchidas?"*

Resposta dada antes de reformular: `classesPt` **não vem do pack**. `adaptSpell:301` traduz por lookup em `CLASS_PT` (13 classes), o pack só preenche `class` em inglês — que é o que o `pack.schema.json` já espera. Classe fora da tabela cai no fallback `|| c` e aparece crua (política WR-05). `CLASS_PT` já é `Object.create(null)` por CR-03. Efeito colateral: `remapClassFilter` vira código morto.

| Opção | Descrição | Selecionada |
|-------|-----------|-------------|
| Traduzir rótulo, filtrar valor do pack | `formatValue` mapeia via `CLASS_PT`; `Set` de filtro guarda o valor do pack | ✓ |
| Deixar classe no idioma do pack | Chips "Wizard/Cleric" em UI PT; mantém `remapClassFilter` vivo | |
| Você decide | Planner escolhe | |

## Papel do toggle PT/EN

### Q1 — O que o toggle controla

| Opção | Descrição | Selecionada |
|-------|-----------|-------------|
| Só o idioma da UI | `setUiLang` substitui `onSwitch`; perde `versions`/`versionKey`; sempre habilitado; mata o modo de falha que originou a fase | ✓ |
| UI + tenta acompanhar o conteúdo | Preserva o gesto de 1 clique, mas reintroduz o acoplamento e muda de comportamento conforme o registro | |
| Dois controles separados no rodapé | Explicita o modelo novo, mas o segundo controle nasce para ficar inerte pós-Fase 6 | |

**Notas:** Confirmado no código que `HifiLangToggle` e `HifiThemeToggle` já ficam lado a lado no fim do rodapé desktop (`:1598-1600`), resultado de um pedido do usuário em sessão anterior — placement não foi reaberto.

### Q2 — Toggle no mobile

| Opção | Descrição | Selecionada |
|-------|-----------|-------------|
| Sim, ao lado do toggle de tema (`:2547`) | Espelha o pareamento do desktop; depois de Q1 é uma linha | ✓ |

**Notas:** Achado que motivou a pergunta — `HifiThemeToggle` **está** montado no mobile (`:2547`), `HifiLangToggle` não. Sem essa adição a fase entregaria um app onde usuários mobile não conseguem trocar de idioma, contra o critério 3.

## Link compartilhado

### Q1 — O idioma da UI viaja no link?

| Opção | Descrição | Selecionada |
|-------|-----------|-------------|
| Não — sempre local de quem abre | Segue o precedente do tema, que já não viaja; um `?lang=` sobrescreveria preferência salva (P-01) | ✓ |
| Sim, adiciona `?lang=` | Reproduz o que o remetente via; abre precedente para `?theme=` | |
| Você decide | Planner escolhe | |

**Notas:** Levantamento apresentado antes — `?spell=` já usa slug EN hardcoded; `hifiShareViewUrl` carrega `q`/`f.*`/`prep`/`v` e como `v` viaja, valores de filtro em idioma de pack continuam casando; `buildSpellLink(s, lang)` tem `lang` como parâmetro morto.

### Q2 — Filtro de classe órfão: 04.1 ou backlog?

| Opção | Descrição | Selecionada |
|-------|-----------|-------------|
| Backlog | Bug pré-existente e ortogonal; encaixa na Fase 5 ou na 6 (MIGR-01, mesma classe de problema) | ✓ |
| Dobrar na 04.1 | Código está quente, mas engorda uma fase que é pré-requisito do milestone | |

**Fechamento da área:** o usuário pediu "mais perguntas". Foi informado de que o caminho `?build=` usa `lang` só para o nome de fallback do personagem e o sufixo `(importado)` — chrome gerado, sem decisão — e que o payload carrega chaves `hifiSpellKey` (EN puro). Registrado também um efeito colateral positivo: com `uiLang` próprio, o effect de `?build=` (deps `[]`) passa a ler um valor síncrono, então o toast de import sai no idioma certo sempre, não só quando o registro de versões chegou primeiro. Nenhuma decisão restante, e o usuário avançou.
