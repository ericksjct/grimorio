# Phase 04.1 Plan 03: Derivar versionLang no CharacterEditor Summary

**CharacterEditor now derives the active pack's language locally (`versionLang`, memoized on the existing `spellVersion` counter) and uses it for both spell-name call sites, so the editor's spell names always match the grimoire's language regardless of which language the interface chrome is in.**

## Performance

- **Duration:** ~15 min
- **Tasks:** 2/2 completed
- **Files modified:** 2 (1 created, 1 modified)

## Accomplishments
- `v11-character-editor.jsx` gained a `versionLang` `React.useMemo` right after the `allSpells` memo, reading `window.getCurrentSpellVersion()?.lang` with fallback `'ptbr'`, depending only on the pre-existing `spellVersion` counter (D-08) — no new listener, no new state, no new prop at any of the editor's 3 mount points
- The search-filter call site (`filteredSpells`) and the rendered spell-name call site both switched from `spellName(s, lang)` to `spellName(s, versionLang)` (D-01), and `versionLang` was added to `filteredSpells`'s dependency array
- `CharacterEditor`'s `lang` prop is completely untouched — it still drives every `tt`/`T`/`window.bilingual(lang)` chrome string in the file
- New `scripts/check-editor-version-lang.tests.ps1` proves the wiring with 4 positive assertions (memo shape/dependency, both call sites, exact call-site count, prop signature intact, `bilingual(lang)` unchanged) and 2 negative assertions (no stale `spellName(s, lang)`, exactly one `hifi-spells-source-changed` listener) — confirmed RED against the pre-Task-1 file content via `git show` (no `git stash`, per worktree prohibition), confirmed GREEN after
- Full existing test suite (`scripts/run-tests.ps1`, 26 scripts) still passes with no regressions
