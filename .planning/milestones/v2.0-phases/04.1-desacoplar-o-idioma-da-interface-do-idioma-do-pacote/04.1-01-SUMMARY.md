# Phase 04.1 Plan 01: Decouple UI language state from active spell version Summary

**`uiLang` is now App's own React state (index.html), seeded by `spellbook-ui-prefs.lang -> detectLang()`, with `window.__setUiLang` wired for the toggle in plan 02 and three new I18N-01/02/03 requirement IDs registered in REQUIREMENTS.md.**

## Performance

- **Duration:** ~20 min
- **Tasks:** 3/3 completed
- **Files modified:** 4 (1 created, 3 modified)

## Accomplishments
- `.planning/REQUIREMENTS.md` now has a `### I18N — Idioma da interface` section with I18N-01/02/03, and the Traceability table/Coverage block updated from 19 to 22 total requirements
- `index.html`'s `App` component owns `uiLang`/`setUiLang`, initialized from `initial.lang || detectLang()` — no longer derived from `langOfVersionKey(initialVersionKey)` (that helper is now dead code and was removed)
- The `hifi-spells-source-changed` handler only calls `setVersionKey(e.detail)`; it no longer reads or writes the UI language
- `window.__setUiLang` registered/cleaned up alongside the other global setters, routing its argument through `normLang` (i18n.jsx) before calling `setUiLang`
- `<html lang>` and `og:locale` now track `uiLang`
- `savePrefs` still writes the `lang` key (unchanged persisted contract, D-17), fed by `uiLang`
- New `scripts/check-ui-lang-state.tests.ps1` proves the decoupling with positive and negative source assertions; confirmed red against the pre-Task-2 `index.html` (via `git show ca3a2b0:index.html`, not `git stash` — stash is prohibited in worktree mode)
