## Test Pattern — PowerShell static-assertion scripts (correcting CONTEXT.md)

CONTEXT.md's "Established Patterns" section states "Sem suíte de testes automatizada: verificação é QA manual" — **this is incorrect**. `scripts/` contains **25** `check-*.tests.ps1` files that assert against source text via regex, run individually with `powershell -File scripts/<name>.tests.ps1`, `$ErrorActionPreference = 'Stop'` + `throw` on failure, single `Write-Output` success line on pass, no test framework/runner file, no CI config found wiring them together (each is invoked standalone). The planner should write **executable** `acceptance_criteria` as new scripts in this family, not defer everything to manual QA.

**Structure, extracted from the 4 named as prior art for D-02/D-04/D-12/D-18:**

`scripts/check-school-filter-labels.tests.ps1` (full file, 24 lines) — asserts a function exists, a formatter is wired at two call sites, one desktop and one mobile:
```powershell
$ErrorActionPreference = 'Stop'
$repoRoot = Split-Path -Parent $PSScriptRoot
$uiPath = Join-Path $repoRoot 'v10-hifi.jsx'
$ui = Get-Content -Raw -LiteralPath $uiPath

if ($ui -notmatch 'function\s+hifiSchoolFilterLabel') { throw 'Missing school filter label formatter.' }
if ($ui -notmatch 'formatValue\s*=\s*\{\s*cat\.formatValue\s*\}') { throw 'Desktop school filter options are not wired through a formatter.' }
if ($ui -notmatch '\{formatValue\(v\)\}') { throw 'FilterChipDropdown still renders raw option values.' }
if ($ui -notmatch 'hifiSchoolFilterLabel\(v,\s*versionLang\)') { throw 'Mobile school filter pills still render raw school keys.' }

Write-Output 'School filter options render formatted labels.'
```
**IMPORTANT for the planner:** the last assertion above (`hifiSchoolFilterLabel\(v,\s*versionLang\)`) is now WRONG per D-02 — the mobile pill call site moves to `uiLang`. This existing test script must be UPDATED (not just relied on) as part of any plan touching `hifiSchoolFilterLabel`'s argument, or it will start failing/passing for the wrong reason.

`scripts/check-class-filter-labels.tests.ps1` (19 lines) — same shape, asserts `hifiTitleCaseFilterLabel` wired at desktop (`formatValue: v => hifiTitleCaseFilterLabel(v)`) and mobile call sites. D-04 replaces title-casing with `CLASS_PT` lookup — this script's regexes will need equivalent updates once the class-filter formatter changes.

`scripts/check-browser-language-detection.tests.ps1` (19 lines) — asserts against `index.html` instead of `v10-hifi.jsx`: a `browserLanguageCandidates` function exists, it inspects the full `navigator.languages` array (not just `navigator.language`), and the pt-detection predicate is `candidates.some(l => l.startsWith('pt'))`. Template for a new D-12 regression script (`detectLang()`/`defaultVersionKeyForLang` staying wired to browser detection for the initial *version*, decoupled from `uiLang`'s own boot resolution).

`scripts/check-class-filter-options.tests.ps1` (19 lines) — asserts a *negative*: a hardcoded 6-class regex list must NOT appear in `v10-hifi.jsx` (guards against regression to the old fixed caster list). Template pattern for asserting dead-code removal, applicable to `remapClassFilter` (D-04) and the `lang` param of `buildSpellLink` (D-16): assert the removed pattern's regex does NOT match, e.g.
```powershell
if ($ui -match 'function\s+remapClassFilter') { throw 'remapClassFilter should have been removed (D-04).' }
```

**Invocation convention:** no shared runner script exists; each `.tests.ps1` is run standalone (`powershell -ExecutionPolicy Bypass -File scripts/check-X.tests.ps1`), exit code non-zero on `throw`. A GSD plan's `acceptance_criteria` can reference "run `scripts/check-<name>.tests.ps1`, expect exit 0 and the success `Write-Output` line" as a concrete, automatable check instead of "manually verify in the browser."
