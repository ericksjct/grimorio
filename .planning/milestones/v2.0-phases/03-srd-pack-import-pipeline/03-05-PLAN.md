Acrescente a `pack-import.jsx`:

**`_readFileText(file)`** — recebe um `File` do `input[type=file]`. Antes de ler qualquer byte, compara `file.size` com `MAX_PACK_BYTES` e chama `_fail` com o código de tamanho excedido quando maior, citando o tamanho em MB com uma casa decimal. Só então lê com `file.text()` e devolve a string. Comentário curto: o tamanho do `File` é conhecido sem ler nada, então o caminho local não precisa de leitura incremental.

**`_fetchText(url)`** — implementa PKG-03 e a metade remota de D-08:
1. `fetch(url)` dentro de `try`/`catch`. Uma rejeição do `fetch` (bloqueio de CORS, DNS, offline) vira `_fail` com o código de falha de busca, preservando a mensagem original do navegador no texto. Não classifique CORS por heurística de string — o navegador não distingue; o código único cobre todos os casos de "não consegui buscar".
2. Resposta com `res.ok` falso também vira o código de falha de busca, citando o `res.status`.
3. Se o cabeçalho `Content-Length` estiver presente e for maior que `MAX_PACK_BYTES`, falha com o código de tamanho excedido ANTES de ler o corpo.
4. Independentemente do cabeçalho, limite os bytes efetivamente lidos: obtenha `res.body.getReader()` e acumule os `Uint8Array` num array, somando `value.byteLength`. Ao ultrapassar `MAX_PACK_BYTES`, chame `reader.cancel()` e falhe com o código de tamanho excedido — sem bufferizar o resto. No fim, decodifique o acumulado com `TextDecoder`.
5. Fallback quando `res.body` não existir (navegador sem streams no `fetch`): use `await res.text()` e, em seguida, meça o tamanho real com `new TextEncoder().encode(text).byteLength`, falhando com o código de tamanho excedido se ultrapassar. Comentário `ponytail:` explicando que este ramo bufferiza antes de checar, e que o teto de 10 MB é pequeno o bastante para isso ser aceitável como degradação em navegador antigo.

**Não** adicione retry, timeout configurável, nem qualquer forma de proxy ou serviço de contorno de CORS. A limitação de CORS é explicada ao usuário pela UI (PKG-03, D-12), nunca contornada por um intermediário — a URL do pacote e o conteúdo dele não podem transitar por servidor que o projeto não controla, e o projeto tem restrição travada de não ter backend.

**`_install(text)`** — o funil único, na ordem exata:
1. `const parsed = parsePackText(text)` — rejeita JSON malformado e chaves bloqueadas.
2. `validatePack(parsed)` — rejeita fora do schema.
3. `const { pack, changedFields } = sanitizePack(parsed)`.
4. `const metas = await window.pluginStore.listPacks()` e monte a lista de identificadores já em uso a partir de `meta.source` de cada um.
5. `const identifier = freeIdentifier(pack.meta.source, existentes)`.
6. Monte o registro: `pack.meta.source = identifier`, `pack.meta.spellCount = pack.spells.length`, e o registro final `{ id: identifier, meta: pack.meta, spells: pack.spells }`. Descarte qualquer chave `id` que tenha vindo do arquivo — o identificador é sempre recalculado.
7. `await window.pluginStore.putPack(registro)` — a ÚNICA gravação da fase.
8. Devolva `{ identifier, spellCount: pack.spells.length, changedFields }`.

Nenhum passo pode ser reordenado: gravar antes de validar ou antes de sanitizar é exatamente a falha que o PKG-04 e o PKG-05 existem para impedir, e o script de checagem assere essa ordem por posição no arquivo.

Estenda o bloco de exposição existente para incluir `sanitizePack`, `installFromFile` e `installFromUrl` junto das cinco chaves já expostas.
