# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract:** the minimal-and-functional import surface (PKG-02/PKG-03: file picker + URL field, success/error messaging, CORS notice) and the static pack-format docs page (PKG-01). Per D-12, this is explicitly **not** final UX — Phase 5 (discuss-gated) reshapes where the import surface lives (drawer vs. own screen, desktop vs. mobile) and adds the pack manager/version selector around it. This contract only needs to hold up long enough for Phase 5 to reuse the underlying logic.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable — no `components.json`, no bundler; React + Babel standalone loaded via pinned CDN `<script>` tags, JSX transpiled in-browser (confirmed: `package.json` has no build/dev script, only unrelated OpenSpec tooling deps) |
| Component library | none — hand-rolled CSS component set already established in `hifi-tokens.css` (`.hifi-btn-primary`, `.hifi-btn-secondary`, `.hifi-btn-ghost`, `.hifi-input`, `.hifi-pill`, `.hifi-icon-btn`, `role="dialog"` panel shell). Reuse these classes verbatim for every new element in this phase — do not invent parallel button/input styles. |
| Icon library | none — inline hand-authored SVG per existing convention (e.g. the prepared-spell ribbon in `v10-hifi.jsx`). No icon package to add for this phase; a file-picker/URL toggle needs at most 1-2 new inline SVGs (or plain text labels — prefer text, this is a minimal-UI phase). |
| Font | `Marauder Text` (body/serif prose), `Texturina` (display headings, small-caps), `JetBrains Mono` (mono labels/chrome) — all self-hosted `@font-face` already declared in `hifi-tokens.css`. UI chrome (buttons/inputs/labels) uses `ui-sans-serif, system-ui, ...` per the existing rule at the bottom of `hifi-tokens.css`; only spell/content prose and the docs page's descriptive text use the serif faces. |

**Theming constraint (carried over from Phase 1):** every new surface must render correctly across all 6 themes × light/dark (Catppuccin, Solarized, Nord, Monokai, Parchment, Daylight) using CSS custom properties (`var(--base)`, `var(--surface0)`, `var(--accent)`, etc.) — never a hardcoded hex in a new component. This is a hard carry-over from Phase 1's animation verification, not new scope.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, gap between mode-toggle tabs |
| sm | 8px | Compact spacing (label-to-input gap, error message top margin) |
| md | 16px | Default element spacing, dialog body padding |
| lg | 24px | Section padding within the docs page |
| xl | 32px | Layout gaps between docs page sections |
| 2xl | 48px | Major section breaks (docs page hero → field reference) |
| 3xl | 64px | Not expected to be needed at this phase's scale — reserved |

**Exceptions (pre-existing project convention, reuse verbatim, do not "fix" to the 4px grid):** `.hifi-input` (`padding: 7px 14px`) and `.hifi-btn-secondary` (`padding: 7px 16px`) use odd vertical padding deliberately, to optically center content inside the project's canon control height (25px mobile / 30px desktop, enforced by `hifi-tokens.css`'s "CANON DE TAMANHO" block). Any new input or secondary button in this phase's import form inherits these classes unmodified — do not round their padding to 8px.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 10px | 400 (uppercase, `letter-spacing: 0.08em`, JetBrains Mono — matches `.hifi-section-label`/`.hifi-mono`) | 1.4 |
| Heading | 20px | 700 | 1.2 |
| Display | 28px | 700 | 1.15 |

- **Body** — import form field text, docs page prose paragraphs, error/success messages. Class: default `.hifi` inherited serif for docs prose; `ui-sans-serif` stack for form chrome (matches `.hifi-input` today).
- **Label** — "IMPORTAR PACOTE" section eyebrow, field hints ("Máx. 10 MB", CORS notice), docs page field-reference row labels.
- **Heading** — import dialog title ("Instalar pacote" / "Install pack"), docs page section headers ("Campos do manifesto", "Exemplo de pacote").
- **Display** — docs page top title ("Formato do Pacote" / "Pack Format") only. Texturina, small-caps, matches `.hifi-display`.

Only 2 weights used project-wide (400 regular, 700 bold) — do not introduce a third.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--base)` | Dialog/docs-page background, follows active theme |
| Secondary (30%) | `var(--surface0)` / `var(--mantle)` | Import dialog panel surface, docs page code blocks, input backgrounds (`.hifi-input` uses `--mantle`) |
| Accent (10%) | `var(--accent)` | Reserved for: the primary "Instalar pacote" submit button, the active File/URL mode toggle, focus rings (`:focus-visible`, already global), links inside the docs page prose (`.hifi-rich a`) |
| Destructive | `var(--red)` | Reserved for: PKG-04 rejection messages (malformed JSON, oversize, schema-invalid, duplicate proto-pollution keys), CORS-fetch-failure messages. **No delete/removal confirmation exists in this phase** (pack removal ships in Phase 5, MGMT-02) — `--red` here is error-signaling only, not a destructive-action confirmation. |

Accent reserved for exactly: submit button background, active mode-toggle tab, focus ring outline, docs-page inline links. Never used for plain body text, card borders, or decorative elements.

**Focal point.** On the import surface, the eye lands first on the **File/URL mode toggle** (the only accent-filled control above the fold, and the decision the user must make before anything else), then on the **"Instalar pacote" submit button** as the terminal action — everything between them (URL field, size hint, CORS notice) is supporting chrome at Body/Label weight. On the docs page, the focal point is the **Display-size page title**, followed by the example-pack JSON block, which is the artifact a pack author actually came for.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | E1 import-form (form) | ✅ covered | Untouched form shows the idle file-picker button and an empty URL field (mutually exclusive tabs/toggle), the CORS-hosts notice, the size hint, and a link to the docs page, before any input — copy in the "Empty state heading/body" rows above. |
| loading | E1 import-form (form) | ✅ covered | Submit button label switches to "Instalando…"/"Installing…" and disables; file/URL inputs disable for the duration of the validate→sanitize→write pipeline. | error | E1 import-form (form) | ✅ covered | Every PKG-04 rejection renders inline in `var(--red)` directly under the active input; transient fetch/CORS failures also fire the existing toast (`useHifiToast`/`hifi-toast` event, `kind:'err'`) — see the "Error state" row in `## Copywriting Contract` for the exact per-reason strings. The error clears on the next input change; the form stays filled so the user can correct rather than re-enter. |
| partial | E1 import-form (form) | ✅ covered | File and URL are mutually exclusive input modes (tab/toggle, never two simultaneously-active fields); submit stays disabled until exactly one mode has a non-empty value, so "both filled" or "neither filled" never reaches the pipeline. A pack that parses but fails schema validation is rejected whole — no partial install, nothing written to storage (PKG-04). |
| overflow | E1 import-form (form) | ✅ covered | The dialog panel caps at `max-height: 80vh` with `overflow-y: auto` on its body (existing `role="dialog"` shell convention in `hifi-tokens.css`); the header and the submit row stay visible. A long selected filename renders in `.hifi-mono` with `text-overflow: ellipsis` on a single line, full name in `title`. Error messages wrap, never scroll horizontally. |
| long-text | E1 import-form (form) | ✅ covered | URL input uses `.hifi-input` with native single-line text overflow (no custom truncation). The success message names the full applied identifier including any D-09 suffix in `.hifi-mono`, wrapping with `overflow-wrap: anywhere` rather than clipping — a long homebrew `source` string must stay fully readable, since it is the identifier the user will look for later. |
| populated | E2 pack-docs-page (list-collection) | ✅ covered | Happy path at typical volume: Display-size title → short intro prose → manifest field-reference table (~8–12 rows) → spell field-reference table (~10–15 rows) → one complete example pack in a monospace block → CORS-compatible-hosts note → link to `pack.schema.json`. Single-column, `max-width` capped for line length at Body size; sections separated by the 48px `2xl` step. |
| overflow | E2 pack-docs-page (list-collection) | ✅ covered | The example-pack JSON block and both field-reference tables render in a monospace, horizontally scrollable container (`overflow-x: auto`, no wrap) — matches the existing JetBrains Mono chrome convention, never silently clipped. On narrow viewports the tables scroll rather than reflowing into stacked cards. |
| zero-one-many | E2 pack-docs-page (list-collection) | ✅ covered | The field-reference tables are authored static content with a fixed, non-zero row count — zero is not a reachable state. | long-text | E2 pack-docs-page (static-content) | ✅ covered | Prose sections (manifest field descriptions, CORS/hosts explanation) use `.hifi-rich` paragraph rhythm (already defined in `hifi-tokens.css`) — normal wrapping, no truncation; this is a static reference page, not a fixed-height card. | loading | E2 pack-docs-page | ⊘ dismissed | Served as part of the app bundle with no runtime `fetch` — the schema link is an anchor, not an in-page load. No loading state exists to design. Classifier `form` cue was a false positive (user-confirmed). |
