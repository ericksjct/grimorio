Acrescente a `pack-import.jsx`:

**`_checkField(path, spec, value)`** — helper privado que valida UM valor contra UMA entrada de tabela. Falha via `_fail` com o código de schema inválido e mensagem `packImport.validate: ` + `path` + explicação do que era esperado. Regras por `type`:
- `'string'` — tem de ser string; se a spec tiver `minLength`, comprimento mínimo; se tiver `pattern`, casar a regex; se tiver `enum`, pertencer ao conjunto.
- `'integer'` — número inteiro finito; respeitar `min`/`max` quando presentes.
- `'boolean'` — booleano estrito.
- `'string[]'` — array cujos itens são todos string.
- `'string|null'` — string ou `null`.

**`_checkObject(path, fields, obj)`** — helper privado genérico: para cada entrada de `fields`, se o valor estiver ausente e a entrada for obrigatória, falha nomeando o campo; se estiver presente, chama `_checkField`. Depois, varre as chaves próprias de `obj` e falha na primeira que não estiver em `fields`, nomeando a chave desconhecida — este é o equivalente do `additionalProperties: false` do schema. Nunca remove nem corrige a chave desconhecida; rejeita.

**`validatePack(pack)`** — ordem exata:
1. `pack` precisa ser objeto simples; senão falha.
2. Falha se alguma chave própria de topo estiver fora do conjunto `id`, `meta`, `spells`. `id` é tolerado (decisão A-02: `pluginStore.exportPack()` serializa o registro verbatim incluindo a chave de topo `id`, e o ciclo exportar→reimportar precisa continuar funcionando); o import recalcula o `id` e não confia no que veio no arquivo.
3. `meta` precisa existir e ser objeto; valida com `_checkObject` contra `META_FIELDS`, exceto a entrada `license`, que é validada separadamente com `_checkObject` contra `LICENSE_FIELDS` sob o caminho `meta.license`.
4. `spells` precisa ser array com pelo menos 1 item (espelha `minItems: 1` do schema; um pacote vazio criaria entrada fantasma no seletor de versões da Fase 5). Cada item é validado com `_checkObject` contra `SPELL_FIELDS`, sob o caminho `spells[i]`.
5. Falha na PRIMEIRA violação encontrada — mensagem única e específica, sem acumular lista. O usuário corrige uma coisa por vez e o custo de percorrer 500 magias inteiras para montar um relatório não se paga.

`validatePack` não retorna valor e não modifica `pack`. Não coage tipos, não preenche default, não normaliza nada.

**`freeIdentifier(base, existingIds)`** — função pura. `base` é o `meta.source` que passou na validação; `existingIds` é um array de identificadores já em uso. Se `base` não estiver em `existingIds`, devolve `base` inalterado. Senão devolve `base` + `-` + o menor inteiro a partir de 2 que produza um identificador ausente de `existingIds`. Comparação por igualdade exata de string, sensível a maiúsculas/minúsculas, sem normalização Unicode — a mesma regra que `pack.schema.json` documenta. Comentário `ponytail:` explicando que `pluginStore.putPack()` é `store.put` (upsert) e sobrescreveria em silêncio, então esta função é obrigatória ANTES da gravação, não uma cortesia.

**Bloco de exposição** no fim do arquivo, no formato de `window.pluginStore`: `window.packImport = { MAX_PACK_BYTES, PACK_ERROR_CODES, parsePackText, validatePack, freeIdentifier };`. O plano 03-05 acrescenta três chaves a este mesmo objeto.
