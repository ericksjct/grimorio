Abertura do banco:
- `openDB()` — devolve uma Promise de `IDBDatabase`. Usa `indexedDB.open(DB_NAME, DB_VERSION)`. No handler `onupgradeneeded`, cria o object store `STORE` com `{ keyPath: 'id' }` apenas se ele ainda não existir (checar `db.objectStoreNames.contains(STORE)`). `onsuccess` resolve com `req.result`; `onerror` rejeita com `req.error`. Também tratar `onblocked` rejeitando com um erro claro em vez de ficar pendurado para sempre.
- Memoizar a Promise de abertura numa variável de módulo `_dbPromise`, mesmo padrão de dedup de `_pending` em `spells-data-loader.jsx`: chamadas concorrentes compartilham a mesma abertura em vez de abrir o banco N vezes. Se a abertura falhar, limpar `_dbPromise` para que a próxima chamada tente de novo (não cachear a falha — mesma decisão já documentada no loader).

Helper privado de transação:
- `_tx(mode, fn)` — abre `db.transaction(STORE, mode)`, chama `fn(store)` e devolve uma Promise que resolve no `tx.oncomplete` e rejeita no `tx.onerror` E no `tx.onabort`, propagando `tx.error` (ou o erro da request, quando `tx.error` for nulo). Nunca resolver no `req.onsuccess` de uma escrita — só o `oncomplete` da transação prova que o dado foi commitado. Para leituras, guardar o `req.result` numa variável e resolver com ele no `oncomplete`.

Validação de forma, ANTES de qualquer transação:
- `_assertPackShape(pack)` — lança `TypeError` com mensagem específica quando: `pack` não é objeto; `pack.id` não é string não-vazia; `pack.meta` não é objeto; `pack.spells` não é array. Chamada como primeira linha de `putPack()`, de modo que um registro malformado nunca chega a abrir transação — garantia de "sem escrita parcial" na origem.

Operações públicas (todas async, todas devolvendo Promise):
- `putPack(pack)` — valida a forma, então `store.put(pack)` dentro de uma transação `'readwrite'`. Resolve sem valor no commit. Rejeita propagando o erro ORIGINAL do IndexedDB, com a propriedade `name` intacta (ex.: `'QuotaExceededError'`) — não envolver em `new Error(...)` genérico, não substituir a mensagem. O chamador (Fase 3/5) é quem decide o toast.
- `getPack(id)` — transação `'readonly'`, `store.get(id)`. Resolve com o registro completo `{ id, meta, spells }` ou `null` quando não existir (normalizar `undefined` para `null`, seguindo a convenção do projeto de "sempre null, nunca undefined").
- `getSpells(id)` — transação `'readonly'`, `store.get(id)`. Resolve com `record.spells` quando existir, senão `[]`. NÃO transforma, filtra, ordena, clona-em-profundidade nem normaliza os itens: devolve o array cru como foi gravado. `adaptSpells()` continua o único ponto de normalização (STOR-01).
- `listPacks()` — transação `'readonly'`, `store.getAll()`, resolve mapeando cada registro para `r.meta` (só os metas, nunca os blobs de spells). Registros sem `meta` são filtrados fora em vez de virarem `undefined` na lista.
- `deletePack(id)` — transação `'readwrite'`, `store.delete(id)`, resolve no commit.

Tratamento de erro (deliberadamente diferente do resto do codebase):
- NENHUM bloco catch vazio neste arquivo. `.planning/codebase/CONCERNS.md` registra o engolimento silencioso de erros como dívida sistêmica e a falta de tratamento de quota como bug conhecido; esta camada nova não repete nenhum dos dois. Marcar essa decisão com um comentário `// ponytail:` no topo da seção de erro explicando que a camada de armazenamento propaga em vez de engolir, e que quem trata a UI é o chamador.

ASVS L1. `security_block_on: high` — nenhuma ameaça `high` sem mitigação pode passar.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| chamador → `pluginStore.putPack()` | JSON de pacote de origem não confiável (arquivo do usuário / URL, a partir da Fase 3) cruza para o armazenamento durável |
| IndexedDB → `pluginStore.getSpells()`/`getPack()` | Dado persistido volta para o runtime do app e, a partir da Fase 4, alimenta `adaptSpells()` e os sinks de render |
| origem do app → IndexedDB | Qualquer script rodando na origem (incluindo CDN comprometida) tem acesso total ao store |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | `putPack()` / registro em `packs` | medium | mitigate | `_assertPackShape()` rejeita registros malformados antes de qualquer transação; `plugin-store.jsx` faz APENAS acesso explícito por campo (`record.spells`, `r.meta`) — nenhum `Object.assign`, spread profundo ou deep-merge sobre dado não confiável, que é o vetor real de prototype pollution.
