Adicionar uma variável de módulo `_persistPromise` (Promise em voo, para dedup de chamadas concorrentes — mesmo padrão de `_pending` em `spells-data-loader.jsx`) e `_persistState` (último resultado conhecido, inicializado como `null`).

`requestPersistence()` — async, sempre resolve, NUNCA lança. Devolve um objeto com três campos booleanos: `supported`, `persisted`, `requested`.
- Se `navigator.storage` não existir ou `navigator.storage.persist` não for função: resolve `{ supported: false, persisted: false, requested: false }`.
- Se já houver `_persistPromise` em voo, devolve essa mesma Promise (duas chamadas paralelas produzem no máximo uma requisição de persistência e resolvem com o mesmo objeto).
- Caso contrário: consulta primeiro `navigator.storage.persisted()`. Se já for `true`, resolve `{ supported: true, persisted: true, requested: false }` SEM chamar `persist()` — este curto-circuito é o comportamento idempotente exigido: com a persistência já concedida, uma segunda chamada não emite uma segunda requisição.
- Se ainda não estiver concedida, chama `navigator.storage.persist()` e resolve `{ supported: true, persisted: <resultado>, requested: true }`. Não cachear permanentemente um resultado negado: uma negação hoje pode virar concessão depois (ex.: usuário instala o PWA), então uma chamada futura deve poder tentar de novo. Só a Promise em voo é deduplicada, não o resultado final.
- Qualquer erro lançado pelas APIs do navegador é capturado e convertido em `{ supported: true, persisted: false, requested: true }` com o erro registrado via `console.warn` — nunca uma rejeição não tratada, nunca um bloco catch vazio. Este é o único ponto do arquivo onde um erro é absorvido em vez de propagado, e o comentário ao lado deve dizer por quê: persistência é best-effort por definição e não pode derrubar o boot.
- Em todos os caminhos, gravar o objeto resultado em `_persistState` antes de resolver, e limpar `_persistPromise` no `finally`.

`getPersistenceState()` — síncrona, devolve `_persistState` (o último resultado) ou `null` se `requestPersistence()` ainda não terminou. É a superfície que a Fase 5 pode ler para exibir o estado no gerenciador.

Chamada de boot, no final do arquivo, imitando o padrão de `spells-data-loader.jsx`: se `document.readyState === 'loading'`, registrar `DOMContentLoaded` para chamar `requestPersistence()`; senão chamar direto. A chamada não é aguardada por nada e não bloqueia nenhum outro caminho de inicialização. Adicionar um comentário curto explicando que isso existe para mitigar a eviction de 7 dias do Safari (STOR-02) e que o resultado é best-effort.
