# Phase 04.1 Plan 04: Content-language ownership in v10-hifi.jsx Summary

**Every call site in `v10-hifi.jsx` that renders pack content (spell name, description, "at higher levels" block) now follows `versionLang` instead of the interface's `lang`, the print payload carries two language keys instead of one, and all 6 content regions (5 HTML sinks + spell name) declare their own `lang` attribute per WCAG 3.1.2.**

- **Duration:** ~35 min
- **Tasks:** 3/3 completed
- **Files modified:** 2 (1 created, 1 modified)

## Accomplishments
- `versionLang` added to `HifiSpellCard`, `HifiDetailContent` and `HifiSessionMode` signatures, propagated through all 6 mount points; `HifiSpellCard`'s custom `React.memo` comparator now compares `versionLang` too, closing a latent staleness bug that only the loader's own per-version cache identity was preventing
- Every `spellName`/`v8Description`/`v8DescriptionHtml`/`v8Upgrade`/`v8UpgradeHtml` call site outside the print family redirected from `lang` to `versionLang` - card (aria-label + rendered name), desktop/mobile detail panel, and all 7 call sites inside `HifiSessionMode` (cast toasts, list/grid render, detail screen, upcast sheet title)
- `buildSpellLink`'s dead `lang` parameter removed (D-16); its two call sites (`hifiCopyLink`, `hifiShare`) now pass one argument
- `hifiShare` signature split into `(s, uiLang, versionLang, show)` - share title in `versionLang`, toast + copy-link fallback in `uiLang` (D-16/D-01); it still has zero call sites in the repo (registered again as a cleanup candidate, per plan instruction not to remove it)
- `hifiPrint`/`hifiPrintList`/`hifiPrintPrepared` split into `(data, uiLang, versionLang, show, ...)`, the `hifi-print-request` `CustomEvent` detail now carries both `uiLang` and `versionLang` keys (with a one-line legacy-key fallback in `HifiPrintRoot` for T-04.1-11), and `HifiPrintCard`'s signature became `{ s, uiLang, versionLang, chunk }` - every print label in `uiLang`, spell name and description content in `versionLang`
- `hifiHtmlLang(lang)` helper added; `lang={hifiHtmlLang(versionLang)}` applied to all 5 `dangerouslySetInnerHTML` sinks (byte-identical `__html:` expressions, confirmed via `git diff`), `HifiSpellName`'s new `lang` prop (applied at all 6 mounts), the print card's spell-name `<div>`, and the invisible card-open button whose `aria-label` is the spell name
- New `scripts/check-content-lang-ownership.tests.ps1`: 8 positive assertions (helper exists, exact 5-sink count with same-element `lang` attribute, `HifiSpellName`/`HifiSpellCard`/`HifiDetailContent`/`HifiSessionMode`/`HifiPrintCard` signatures, `buildSpellLink` arity, search/sort still on `versionLang`, `hifiShare`'s split signature, memo comparator) and 3 negative assertions (`spellName(`/`v8*(` never with `lang`, `tt(versionLang,` never occurs) - confirmed RED against the pre-plan `v10-hifi.jsx` (`git show 394241d:v10-hifi.jsx`, not `git stash` - prohibited in worktree mode) and GREEN after all three tasks

## Deviations from Plan

### Sequencing correction (not a Rule 1-3 bug fix, but flagged per plan's own risk analysis)

**1. Deferred 3 call sites from Task 1 to Task 2 to avoid a ReferenceError window**
- **Found during:** Planning Task 1's edits, before touching any print-related code
- **Issue:** The plan's `<inventory>` lists `spellName(a, lang)` at (then) line 144 (`hifiPrintPrepared`'s sort comparator) and `spellName(s, lang)` at (then) line 312 (`HifiPrintCard`'s rendered name), plus the four `v8Description*`/`v8Upgrade*` fallback calls inside `HifiPrintCard` (then lines 293-296), among the call sites that "migrate in Task 1" (grouped under the 14-site and 13-site counts in `<inventory>`). But `HifiPrintCard`'s signature and `hifiPrintPrepared`'s parameter list only gain `versionLang` in Task 2's own action group ("Assinaturas de despacho" / "`HifiPrintCard`: assinatura passa de `{ s, lang, chunk }` para `{ s, uiLang, versionLang, chunk }`"). Editing these 3 sites' arguments to `versionLang` inside Task 1's commit - before that prop/param existed - would have produced a `ReferenceError` on first print, invisible to any regex-based QA (per the plan's own `<inventory>` §ATENCAO, which explicitly names this exact failure mode for `hifiShare` and the three print dispatchers, but does not explicitly extend the warning to `HifiPrintCard`'s body or `hifiPrintPrepared`'s sort comparator even though they have the identical structural problem).
- **Fix:** Left all 3 sites on `lang` in Task 1's commit; migrated them to `versionLang` in Task 2's commit, in the same commit that adds the `uiLang`/`versionLang` props/params they need. Verified after Task 1 that only these 3 (plus the 4 `v8*` fallback calls in the same component, which have the identical constraint) remained on `lang`, via `grep -nF` for the exact literal call-site strings.
- **Files modified:** `v10-hifi.jsx` (no extra file - same file, different task boundary than a literal reading of `<inventory>` would suggest)
- **Verification:** `scripts/run-tests.ps1` (26 pre-existing scripts) passed after both Task 1 and Task 2's commits; `scripts/check-content-lang-ownership.tests.ps1` (written in Task 3) passes with zero `lang`-argument regressions across the whole file
- **Committed in:** `b761e3f` (Task 1 - sites left untouched) and `7110b07` (Task 2 - sites migrated)
