# Phase 04.1 Plan 05: Filter vocabulary follows the interface language (D-02/D-04) Summary

**Filter category labels, school name, class label and concentration/ritual Yes/No now follow the interface language (`uiLang`) while filter values stay in the pack's language or become canonical literals immune to a mid-session language switch; the dead `remapClassFilter` helper is gone.**

## Performance

- **Duration:** ~15 min (Tasks 1-2); Task 3 checkpoint verified separately (Playwright QA + coordinator approval)
- **Tasks:** 3/3 completed (2 auto + 1 checkpoint)
- **Files modified:** 4 (1 created, 3 modified) + REQUIREMENTS.md

## Accomplishments

- `hifiFilterConfig` called with `uiLang` at both UI mounts (desktop `filterCfg`, mobile `filterCfg`) instead of `versionLang` - category `label`s and the conc/rit `formatValue` now follow the interface language (D-02). The filter engine's own call inside `useHifiAppState` (`:943`) is untouched and stays on `versionLang` - it only ever reads `.get()`, which the D-02 split confirms is language-indifferent.
- `hifiSchoolFilterLabel` called with `uiLang` at both call sites (desktop `formatValue`, mobile pill) - school name follows the interface language, same as the category label it sits next to.
- `conc`/`rit` filter definitions rewritten to produce the canonical literals `'yes'`/`'no'` in both `get` and `values`, with a `formatValue` (the renamed `bool` helper) that translates to `tt(lang, 'value.yes'|'value.no')` only at render time. This closes the failure mode where switching the interface language mid-session with concentration/ritual selected would silently zero the filtered list (the `Set` used to hold a translated string that stopped matching the engine's freshly-translated output).
- `formatValue` plumbing wired for extra filters: the desktop `FilterChipDropdown` mount for extras now passes `formatValue={filterCfg[key].formatValue}` (previously omitted, always rendering raw values); the mobile extras pill applies the same formatter with a `v` fallback when a category has none.
- New `hifiClassFilterLabel(value, uiLang)`: looks up `window.CLASS_PT` (en→pt) when `uiLang === 'ptbr'`, `window.CLASS_EN` (pt→en) otherwise, indexing in lowercase, falling back to the raw value when the key isn't found (covers both "already in the target language" and "homebrew/typo outside the 13 canonical classes"), then applies `hifiTitleCaseFilterLabel` for the initial capital. Reuses the two existing `Object.create(null)` tables from `spells-data-loader.jsx` - no new lookup table, per D-04 and CR-03. Wired at both call sites (desktop `filterCats` class entry, mobile class pill), replacing the previous plain `hifiTitleCaseFilterLabel(v)` call.
- `remapClassFilter` (dead code after D-04 - the class filter `Set` now always holds the pack's own value, so there's nothing left to remap on a version switch) removed along with its call site inside the version-change effect; `setSelectedIdx(null)` and the `prevVersionKeyRef` update survive, since they're unrelated to language.
- Two pre-existing scripts corrected in the same commit that changed the lines they assert on: `check-school-filter-labels.tests.ps1`'s last assertion now looks for `hifiSchoolFilterLabel(v, uiLang)` instead of the pre-Task-1 `versionLang` call site; `check-class-filter-labels.tests.ps1` now asserts `hifiClassFilterLabel(v, uiLang)` at both call sites while keeping its original assertion that `hifiTitleCaseFilterLabel` still exists (it survives as an internal helper).
- New `scripts/check-filter-lang-vocabulary.tests.ps1`: 7 positive assertions (`hifiClassFilterLabel` declared and called twice with `uiLang`, `hifiFilterConfig(uiLang)` called twice, `hifiSchoolFilterLabel(v, uiLang)` called twice, conc/rit canonical literals + `formatValue`, `hifiFilterConfig` still `Object.create(null)`-based, `hifiFilterValues('class', allSpells, versionLang)` untouched, extras `formatValue` plumbing on both screens) and 4 negative assertions (no `remapClassFilter` declaration or call, no `hifiSchoolFilterLabel(v, versionLang)` regression, no `get:` inside `hifiFilterConfig` calling `bool(`, exactly 1 call to `hifiFilterConfig(versionLang)` across the whole file) - confirmed RED against the pre-plan `v10-hifi.jsx` (materialized via `git show 2e66fb5:v10-hifi.jsx` + scratchpad backup/restore, not `git stash` - prohibited in worktree mode) and GREEN after both tasks.
- `I18N-03` marked complete in `REQUIREMENTS.md` (checkbox + traceability table) - it's a multi-plan requirement whose scope is fully covered by 04.1-03 (editor), 04.1-04 (content ownership) and this plan (filter vocabulary) together.
