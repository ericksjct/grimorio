## Premissas do planner

- **Teto de URL 2048 dentro da própria regex** (`{0,2039}` depois de `https://` + 1º
  caractere): não precisa de constante nova. URL https longa demais é `image-invalid`;
  qualquer valor acima de 204800 continua `image-too-large` (teto barato antes da regex).
- **Esquema em minúsculas exatas** (`https://`): `HTTPS://` é rejeitado. É mais estrito que
  o navegador, de propósito — a docs pede `https://`.
- **SVG por URL https** passa no formato (não dá para saber o tipo sem buscar); dentro de
  `<img>` o navegador não executa script de SVG, então não abre XSS.
- **Service worker:** sem mudança de comportamento — o handler de fetch já ignora outra
  origem, exceto `unpkg.com` (uma imagem hospedada lá seria cacheada como recurso de
  dados; aceito). O bump de `CACHE_VERSION` para `grimorio-v6` fica no 08-11, último plano
  de código desta rodada, cobrindo também os arquivos deste plano.
- **CSP:** sem `img-src` hoje, então `https:` já carrega; nenhuma diretiva nova.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `meta.image` do pack de terceiro → `<img src>` | string não confiável vira URL carregada pelo navegador |
| navegador do usuário → host da imagem | a renderização do cartão faz requisição a um host escolhido pelo autor do pack |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-36 | Elevation of Privilege | esquema perigoso em `meta.image` (`javascript:`, `data:text/html`, SVG em `data:`, `http:`, protocolo relativo) | high | mitigate | allowlist ancorada `IMAGE_SRC` (só `data:` raster base64 ou `https://`), checada no import (`_checkImage`) antes de qualquer gravação; provada caso a caso em `check-pack-validator` |
| T-08-37 | Information Disclosure | cabeçalho Referer com a URL do app (e query `?v=`/`?build=`) indo ao host da imagem | medium | mitigate | `<img referrerPolicy="no-referrer">` no `PackThumb`; travado em `check-pack-menu` |
| T-08-38 | Information Disclosure | host da imagem vê o IP e o horário de quem abre o menu | medium | accept | consequência inerente de aceitar URL externa (decisão do usuário, E-03); documentada em `pack-docs.html` (PT/EN) com a recomendação de `data:` para privacidade; nenhuma busca no import, só no render do cartão |
| T-08-39 | Tampering | valor gravado antes desta fase ou IndexedDB adulterado contornando o import | medium | mitigate | `_safeImage` revalida no render com a MESMA `IMAGE_SRC` e o mesmo teto (T-08-23), sem regex local; provado em `check-pack-menu` |
| T-08-40 | Denial of Service | imagem remota lenta, 404, offline ou bloqueada quebrando o cartão | low | mitigate | `onError` → marcador colorido (D-19); `<img>` não bloqueia o menu; import não busca a URL |
| T-08-41 | Tampering | conteúdo da imagem remota muda depois do import (troca por imagem ofensiva, pixel de rastreio) | low | accept | o conteúdo do pack é do autor que o usuário escolheu instalar; remoção do pack resolve; `data:` documentado como alternativa estável |
| T-08-42 | Denial of Service | ReDoS na regex de imagem | low | mitigate | teto de 204800 caracteres checado antes da regex (T-08-11); as duas alternativas são classes simples com quantificador limitado, sem aninhamento |
