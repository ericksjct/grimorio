# Phase 8 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract:** the pack menu that replaces `VersionSelector` and absorbs `PackManager` (D-16) — checkbox multi-select over SRD + homebrew, pack cards with image/title/description (D-17), the color-derived placeholder (D-19), the reserved-slugs section (D-15) — plus the new slug-rename conflict prompt (D-09..D-13). Everything else (spell grid, spell-detail panel, "Também em:" note, character editor orphans) is unchanged visually; this contract does not re-litigate it.

**shadcn gate:** skipped. No `components.json`, no bundler (React + Babel via pinned CDN `<script>` tags, JSX transpiled in-browser — confirmed unchanged since Phase 3). Phases 3 and 5 already made this call for the project (`Tool: none`); re-asking would contradict "don't re-ask what upstream already answered."

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-rolled `hifi-tokens.css` set. Every new element in this phase reuses existing classes verbatim: `.hifi-btn-primary` / `.hifi-btn-secondary` / `.hifi-btn-ghost`, `.hifi-input`, `.hifi-filter-chip` + `.hifi-filter-chip-count`, `.hifi-icon-btn` (flat variant from `.hifi-panel-header`), `.hifi-section-label`, the `role="dialog"` shell (`pack-import-dialog.jsx` chrome + `useDialogA11y`), and the `.hifi-level-0..9` color ramp (reused for D-19, see Color below). No new component classes are introduced. |
| Icon library | none — inline SVG / text glyphs / native controls only. This phase needs: a native `input[type=checkbox]` (styled only via the existing global `:focus-visible` ring), the `▾` caret already used by `VersionSelector`, and a flat `.hifi-icon-btn` glyph (✕ or 🗑, text glyph — no new SVG asset) for the per-row remove affordance — icon-only, so it MUST carry `aria-label` + `title` = the existing `manager.remove` i18n string (bilingual accessible name). |
| Font | `Marauder Text` (card descriptions, dialog body prose), `Texturina` (menu/dialog headings, small-caps), `JetBrains Mono` (section labels, slugs, counts, lang codes) — all self-hosted, already declared in `hifi-tokens.css`. Menu/dialog chrome (checkboxes, buttons, inputs) uses the `ui-sans-serif` system stack per the existing chrome rule. |

**Theming constraint (carried over):** every new surface renders correctly across all 6 themes × light/dark using CSS custom properties — never a hardcoded hex.

## Spacing Scale

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between checkbox and thumbnail, gap inside the lang-dot + code cluster |
| sm | 8px | Gap between thumbnail and title block, vertical rhythm inside a pack-card row |
| md | 16px | Menu/dialog body padding, gap between menu sections (SRD / Instalados / Reservados) |
| lg | 24px | Not used at this phase's scale — reserved |
| xl | 32px | Not used at this phase's scale — reserved |
| 2xl | 48px | Not used at this phase's scale — reserved |
| 3xl | 64px | Not used at this phase's scale — reserved |

**Exceptions (carried over, reuse verbatim, do not "fix" to the 4px grid):** `.hifi-input` (`padding: 7px 14px`) and `.hifi-btn-secondary` (`padding: 7px 16px`) keep their odd vertical padding — this phase's rename-prompt inputs and buttons inherit these classes unmodified.

**New canon value (not a spacing token — a control-size canon, like the existing 25px/30px icon-button rule):** pack-card thumbnail is **32px** square on mobile, **40px** square on desktop. Placed one step above the existing icon-button canon because a two-line title+meta row needs a bigger anchor than a 25/30px icon button.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 10px | 400 (uppercase, `letter-spacing: 0.08em`, JetBrains Mono — `.hifi-section-label`) | 1.4 |
| Heading | 20px | 700 | 1.2 |
| Display | 28px | 700 | 1.15 |

- **Body** — pack card title (700 weight within Body size, no new size step), auto-generated description line, rename-dialog prose, per-row conflict text.
- **Label** — menu section headers ("SRD", "Pacotes instalados", "Slugs reservados"), reserved-slug entries (mono, matches slugs-as-code convention).
- **Heading** — rename-conflict dialog title ("Conflito de slugs" / "Slug conflicts").
- **Display** — **not used this phase.** Kept in the table for contract parity with Phases 3/5; the pack menu and the rename dialog are anchored surfaces (dropdown / bottom sheet / modal), not full pages, so no Display-size title is needed.

Only 2 weights used project-wide (400 regular, 700 bold) — this phase introduces no third weight.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--base)` | Page background behind the chip/dialog (unchanged) |
| Secondary (30%) | `var(--surface0)` / `var(--mantle)` | Dropdown panel / bottom-sheet surface, pack-card row background, thumbnail placeholder background |
| Accent (10%) | `var(--accent)` | Reserved for: checked checkbox state, the primary "Instalar pacote" / "Renomear e continuar" buttons, focus rings, the "✓" current-marker convention carried from `VersionSelector` |
| Destructive | `var(--red)` | Reserved for: PKG-04-style rejection text reused verbatim, live slug-validation errors in the rename prompt (reserved / duplicate / bad-format), oversized/invalid `meta.image` errors |

Accent reserved for exactly: checkbox checked-state fill, primary submit buttons, focus-ring outline, the current-selection checkmark glyph. **Never** used for the color-derived pack thumbnail (D-19 is explicit: that color is menu-only decoration, not an accent signal, and never tints the grid).

**Carried-over convention — no red confirm button.** The "remover pacote" confirm action stays `.hifi-btn-primary` (accent), exactly as in `pack-manager.jsx` today. This repo has never used `var(--red)` for a destructive CONFIRM button, only for error/rejection text (Phase 3 and Phase 5 precedent). This phase does not introduce one.

**Focal point.** In the pack menu, the eye lands first on the checkbox column (the decision the user is there to make), then on the "Instalar pacote" footer button as the terminal action. In the rename-conflict dialog, the eye lands on the conflicting spell names first, then the editable slug inputs, then "Renomear e continuar."

When `meta.edition` is present, insert it before the spell count: `"{autor} · v{versao} · {lang} · {edicao} · {n} {nounSpell}"`. `{lang}` reuses the existing 2-letter mono code (`PT`/`EN`) from `VersionSelector`'s lang-dot convention — no new language-name strings. `{nounSpell}` resolves via the existing `noun.spell.` + `plural(n)` mechanism (same pattern as `print.printing`). |

| Rename cancel / submit | **(new)** `rename.cancel` — PT "Cancelar" · EN "Cancel". **(new)** `rename.submit` — PT "Renomear e continuar" · EN "Rename and continue" |
| Rename submit-disabled hint | **(new)** `rename.submitDisabledHint` — PT "Resolva todos os conflitos para continuar." · EN "Resolve every conflict to continue." |
| Error state — slug validation (live, inline) | **(new)** `rename.errorFormat` — PT "Slug inválido — use letras minúsculas, números e hífens." · EN "Invalid slug — use lowercase letters, numbers, and hyphens." · **(new)** `rename.errorReserved` — PT "Este slug é reservado pelo pacote SRD — escolha outro." · EN "This slug is reserved by the SRD pack — choose another." · **(new)** `rename.errorDuplicate` — PT "Este slug já está em uso por outro pacote instalado." · EN "This slug is already used by another installed pack." |
| Error state — `meta.image` (extends PKG-04 family) | **(new)** `packErr.imageTooLarge` — PT "Imagem do pacote maior que {kb} KB — reduza o arquivo." · EN "Pack image larger than {kb} KB — shrink the file." · **(new)** `packErr.imageInvalid` — PT "Imagem do pacote precisa ser um data: URI de imagem (PNG/JPEG/WebP/GIF)." · EN "Pack image must be an image data: URI (PNG/JPEG/WebP/GIF)." |
| Toast — selection fallback | **(new)** `menu.toastFallbackToDefault` — PT "Pacote removido da seleção — mostrando o pacote padrão." · EN "Pack removed from selection — showing the default pack." Fires only when unmarking/removing the last selected pack empties the selection and D-04's default takes over. Fixes folded-todo item (1): **always** rendered via `tt(uiLang, ...)`, never the pack's own language. |

**Size cap for `meta.image` (Claude's Discretion, D-17):** 200 KB on the `data:` URI string length (well under the pack's existing 10 MB total cap — this is a thumbnail, not pack content). Accepted formats: PNG, JPEG, WebP, GIF, validated by MIME prefix in `pack-import.jsx`, rejected with `packErr.imageInvalid` / `packErr.imageTooLarge` above — same rejection shape as every other PKG-04 check (specific problem + actionable next step, nothing written on failure).

**Color-derived placeholder (Claude's Discretion, D-19):** hash the pack's `source` identifier to one of the existing 10 `--level-N` swatches (reuses the theme-aware level-color ramp already used for spell-level bars — zero new palette). Render as a 32/40px rounded-square (`border-radius: 8px`, `border: 1px solid var(--surface1)`) filled with `var(--level-N)`, with the pack's first uppercase initial centered in `.hifi-mono` at `var(--base)` for legibility. Builtin SRD packs may ship real `meta.image` art instead (D-17) — the placeholder path only applies to homebrew without one.

| error | E1 pack-menu | ✅ covered | `listPacks()` failure falls back to `packErr.unknown` toast and treats the homebrew section as empty (existing `reload()` catch behavior in `pack-manager.jsx`, unchanged). |
| partial | E1 pack-menu | ✅ covered | D-03 mutual exclusivity is enforced live: checking SRD 5.1 unchecks SRD 5.2 in the same state update, so "both SRD editions checked" is never an observable state, not even mid-click. |
| overflow | E1 pack-menu | ✅ covered | Desktop dropdown panel: `max-height: min(72vh, 640px)`; mobile bottom sheet: `max-height: 80vh`. | long-text | E1 pack-menu | ✅ covered | Pack title wraps (`overflow-wrap: anywhere`, never truncated — it's the identifier the user picks by); the auto-description line truncates with `text-overflow: ellipsis` on one line, full text in `title=` (matches Phase 3's filename-truncation precedent). |
| zero-one-many | E1 pack-menu | ✅ covered | One pack marked → chip shows just its label; many marked → "+N" suffix (D-18, language-agnostic numeral, no localization risk). |
| populated | E1 pack-menu | ✅ covered | Typical case: 2 SRD rows + 0-5 homebrew rows + collapsed reserved-slugs `<details>` (matches the existing license `<details>` UX) + pinned footer button. |
| empty | E2 rename-conflict-dialog | ⊘ dismissed | The dialog only ever opens WITH at least one conflict (D-09's trigger condition) — zero conflicts never opens it, so there's no empty state to design. |
| loading | E2 rename-conflict-dialog | ✅ covered | Submit button disables and its label switches to a busy variant while the rename writes to `plugin-store.jsx` — same text-only busy convention as the Phase 3 import submit (no spinner, matches no-icon-library convention). |
| error | E2 rename-conflict-dialog | ✅ covered | Per-row live validation (`rename.errorFormat`/`errorReserved`/`errorDuplicate`) renders in `var(--red)` under the offending input (D-11); submit stays disabled until every row is valid. |
| partial | E2 rename-conflict-dialog | ✅ covered | D-12: canceling at any point aborts the whole operation — nothing written, nothing marked. There is no reachable "half-renamed" state. |
| overflow | E2 rename-conflict-dialog | ✅ covered | A large homebrew import colliding on many slugs scrolls inside the dialog body (`max-height: 80vh`, same modal shell as `pack-import-dialog.jsx`); "aplicar sufixo a todas" and the submit/cancel footer stay pinned. |
| long-text | E2 rename-conflict-dialog | ✅ covered | Third-party spell names are untrusted display strings — same T-05-01 convention as `PackManagerRow`: render as text children, sliced to 64 chars, `overflow-wrap: anywhere`. |
| zero-one-many | E2 rename-conflict-dialog | ✅ covered | Exactly one conflicting slug renders the same full row layout (no singular-only copy branch); "aplicar sufixo a todas" still functions at n=1, just affects one row. |
| populated | E2 rename-conflict-dialog | ✅ covered | Common case is 1-3 conflicts (a homebrew colliding with a couple of SRD/other-homebrew slugs) — layout doesn't special-case count. |
| zero-one-many | reserved-slugs sub-list (nested in E1) | ✅ covered | A reserved slug has exactly one owner (SRD 5.1 XOR 5.2, per D-03) or two (both languages of the same SRD 5.2 edition, per D-03's EN×PT coexistence) — the subitem list under a slug heading is never empty, since a slug is only "reserved" because at least one SRD pack contains it. |
